# photo_heaven — 데이터 모델

> 이 앱이 다루는 데이터가 어떻게 생겼는지 정의합니다.
> 개발자가 아니어도 읽을 수 있게 썼습니다.
> **갱신: 2026-07-16** — UI 방향 확정(살구+세이지 스타일, 이름 톡, 두 아이 필터)에 맞춰 아이·보는사람·한마디 추가.

---

## 전체 구조

```
[앨범] ──1:N──> [사진] ──1:N──> [한마디]
   │              │
   │              └──(어느 아이?)──> [아이]
   ├──1:N──> [아이]
   ├──1:N──> [보는사람]  (이름 톡 · 누가 봤나 · 한마디 주인)
   └──1:N──> [알림받을사람]  (Phase 2)
```

말로 풀면 — **앨범 한 개**(우리집 사진첩)에 **아이 여럿**(준영·서아)과 **사진 여러 장**이 들어간다. 사진마다 "누구 사진"인지 표가 붙을 수 있고, 사진에 **한마디**가 달린다. 앨범에는 **보는 사람 명단**(외할머니·이모…)이 등록돼 있어서 "누가 봤나"와 "누가 한마디를 남겼나"가 성립한다.

> **왜 앨범이 따로 있나?** (1) 오픈소스로 공개하면 설치한 집마다 자기 앨범이 필요하다. (2) 아이를 완전히 따로 관리하고 싶으면 앨범을 둘 만들 수 있다. 기본은 **한 앨범에 아이 여럿**.

---

## 엔티티 상세

### 앨범 (albums)

한 가족의 사진 공간. 링크 주소와 암호가 여기 붙는다.

| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| id | 고유 번호 (자동 생성) | `01H8X...` | O |
| baby_name | 앨범 제목 (화면 상단에 표시. 아이가 여럿이면 "우리집 사진첩" 같은 이름) | `우리집 사진첩` | O |
| share_slug | **비밀 링크 주소.** 추측 불가능한 무작위 문자열(10자 이상) | `x7k2m9p4q1` | O |
| viewer_passcode_hash | **가족용(보기) 암호** 해시. 조부모님이 열람할 때 | `$2b$10$...` | O |
| admin_passcode_hash | **부모용(올리기) 암호** 해시. 가족용과 반드시 다름 | `$2b$10$...` | O |
| created_at | 만든 날짜 (자동) | `2026-07-16` | O |

**보안 주의**
- `share_slug`는 뜻 없는 무작위여야 한다. `baby`·`hayoon` 같으면 남이 찍어서 들어온다
- 암호는 반드시 **해시**로 저장. 원본은 DB에 절대 안 넣는다. 부모/조부모 암호가 나뉘어 있어, 조부모는 봐도 못 올린다

---

### 아이 (children) — *신규*

앨범에 속한 아이 한 명. 두 아이(준영·서아)를 한 앨범에서 이름으로 구분하고, 나이 라벨("태어난 지 2개월")을 붙이려고 둔다.

| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| id | 고유 번호 (자동 생성) | `01H9A...` | O |
| album_id | 어느 앨범 소속인지 | `01H8X...` | O |
| name | 아이 이름 (필터·이름표에 표시) | `준영` | O |
| birthdate | 생일. **"태어난 지 N개월"을 자동 계산**하려고 | `2026-05-14` | X |
| created_at | 만든 날짜 (자동) | `2026-07-16` | O |

**설계 메모**
- 아이가 **한 명이면** 화면에 필터 토글이 안 뜬다. 오픈소스로 남이 한 명만 등록하면 깔끔하게 앨범만 보인다
- `birthdate`가 없으면 나이 라벨을 그냥 안 보여준다(선택). 억지로 요구하지 않는다

---

### 사진 (photos)

올린 사진 한 장.

| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| id | 고유 번호 (자동 생성) | `01H8Y...` | O |
| album_id | 어느 앨범 소속인지 | `01H8X...` | O |
| child_id | **누구 사진인지** (신규). 비어 있으면 "온 가족/미지정" | `01H9A...` | X |
| storage_key | 저장소의 **원본** 파일 이름 | `x7k2m9/orig/01H8Y.jpg` | O |
| thumb_key | **화면용 축소본** 파일 이름 (빨리 뜨게) | `x7k2m9/thumb/01H8Y.webp` | O |
| caption | 한 줄 메모 | `오늘 처음 뒤집었어요` | X |
| taken_at | 찍은 날짜 (사진에 박힌 정보에서 추출) | `2026-07-15 14:32` | X |
| uploaded_at | 올린 날짜 (자동) | `2026-07-16 09:01` | O |
| width / height | 축소본 가로·세로 (배치 안 덜컹거리게) | `1600 / 1200` | O |
| original_width / original_height | 원본 가로·세로 | `4032 / 3024` | O |
| mime_type | 사진 형식 | `image/jpeg` | O |
| file_size_bytes | 원본 용량 | `2411008` | O |

**중요한 설계 두 가지**
1. **원본과 축소본을 둘 다 보관.** 축소본만 남기면 패밀리앨범 무료판의 "화질 압축" 불만을 반복한다. 원본은 안 건드린다
2. **정렬은 `taken_at` 기준**(찍은 날). 비어 있으면 `uploaded_at`으로 대체. 지난주 사진을 오늘 몰아 올려도 제 날짜에 꽂힌다

---

### 보는사람 (viewers) — *신규*

앨범을 보는 가족 한 명. **"누구세요?" 이름 톡** 목록이자, **"누가 봤나"**와 **한마디 주인**의 정체다. 부모가 미리 이름을 등록해두면, 조부모님이 처음 들어올 때 자기 이름을 한 번 고른다(비밀번호 아님).

| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| id | 고유 번호 (자동 생성) | `01H9B...` | O |
| album_id | 어느 앨범 사람인지 | `01H8X...` | O |
| name | 표시 이름 | `외할머니` | O |
| last_seen_at | **마지막으로 본 시각** ("외할머니가 방금 보셨어요") | `2026-07-16 09:40` | X |
| created_at | 등록 날짜 (자동) | `2026-07-16` | O |

**로그인이 아니다**
- 비밀번호가 없다. 앨범 암호를 통과한 뒤 "누구세요?"에서 이름만 고른다 → 그 `id`를 쿠키에 30일 저장
- 그래서 앱 설치·회원가입 없이도 "누가 봤나"와 "누가 한마디 남겼나"가 된다
- **개인정보 없음** — 이름표(외할머니)만 있고 전화번호·이메일은 여기 없다(그건 아래 알림받을사람)

---

### 한마디 (comments) — *신규*

사진에 남긴 짧은 글. "아이고 예뻐라 ❤"

| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| id | 고유 번호 (자동 생성) | `01H9C...` | O |
| photo_id | 어느 사진에 달렸는지 | `01H8Y...` | O |
| viewer_id | 누가 남겼는지 (보는사람) | `01H9B...` | O |
| body | 한마디 내용 (짧게) | `아이고 예뻐라 ❤` | O |
| created_at | 남긴 시각 (자동) | `2026-07-16 09:41` | O |

---

### 알림받을사람 (subscribers) — *Phase 2*

새 사진이 올라오면 문자/텔레그램을 받을 가족. **보는사람과 별개** — 알림 받는 사람은 연락처(개인정보)가 필요하기 때문.

| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| id | 고유 번호 (자동 생성) | `01H8Z...` | O |
| album_id | 어느 앨범 알림인지 | `01H8X...` | O |
| name | 누군지 | `외할머니` | O |
| channel | `sms` 또는 `telegram` | `sms` | O |
| address | 문자면 전화번호, 텔레그램이면 대화 번호 | `010-0000-0000` | O |
| is_active | 알림 끄기/켜기 | `true` | O |
| created_at | 등록 날짜 (자동) | `2026-07-16` | O |

**개인정보 주의** — 연락처는 개인정보다. 이 표 내용이 **GitHub에 절대 올라가면 안 된다.** 코드에 예시로라도 실제 번호를 쓰지 말 것.

## 관계 정리

- 앨범 1개에 → 아이 여럿, 사진 여럿, 보는사람 여럿, 알림받을사람 여럿
- 사진 1장은 → 아이 한 명에 속하거나(선택) 미지정, 한마디 여럿을 가짐
- 한마디 1개는 → 사진 1장 + 보는사람 1명에 묶임
- 앨범이 지워지면 → 그 안의 아이·사진·보는사람·한마디·알림 대상이 함께 지워진다

---

## 왜 이 구조인가

**단순성 — 여전히 로그인은 없다**
회원가입도, 비밀번호 로그인도 없다. 앨범 암호 + "이름 톡" + 30일 쿠키가 전부다. `viewers`는 "사용자 계정"이 아니라 그냥 **이름표 목록**이다. *"회원가입을 없애는 것"이 이 제품의 존재 이유*라는 원칙은 그대로다.

**두 아이를 한 구조로**
- 같이 보기 = 한 앨범 + 아이 여럿 + 필터
- 따로 보기 = 앨범을 둘로
- 한 명인 집 = 아이 1명, 필터 토글 자체가 안 뜸
한 데이터 구조로 세 경우가 다 된다.

**확장성 — 뼈대는 미리**
- **오픈소스 공개**: `albums`가 여러 행이면 그대로 여러 집이 쓴다
- **영상 (Phase 3)**: `photos`에 `media_type` 열 하나만 추가
- **하트 반응**: `comments`가 이미 있으니 같은 방식으로 `reactions`를 붙이면 된다(지금은 안 만듦)

**안 넣은 것과 그 이유**
- `users`·권한 테이블 — 로그인이 없으니 불필요. `viewers`는 이름표일 뿐
- 활동 피드 테이블(누가 뭘 했나 전체 로그) — 과함. "누가 봤나"는 `viewers.last_seen_at`, "한마디"는 `comments`로 충분
- `tags`·`folders` — 날짜순 + 아이 필터면 충분. 조부모님껜 복잡함만 늘린다
