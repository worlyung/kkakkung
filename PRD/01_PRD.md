## 1. 제품 개요

### 한 줄 요약

아기 사진을 부모가 한 번 올리면, 조부모님이 **앱 설치도 회원가입도 없이 링크 하나로** 보실 수 있는 가족 전용 사진 공간.

### 해결하는 문제

**부모 쪽 불편**
카톡으로 매번 사진을 고르고, 양가에 각각 보내고, 며칠 뒤 "그 사진 다시 보내줘" 소리를 듣는다. 사진이 여러 채팅방에 흩어져 나중에 찾을 수도 없다.

**조부모 쪽 불편**
손주 사진은 누구보다 보고 싶은데, 앱을 새로 깔고 계정을 만드는 게 큰 벽이다. 카톡방에 사진이 우수수 올라오면 중요한 걸 놓치고, 스크롤이 지나가면 다시 못 찾는다.

### 핵심 가치 — 왜 이미 있는 걸 안 쓰고 만드는가

조사해보니 **네 가지를 동시에 만족하는 것이 현재 없다.**

| | 앱 설치 없이 링크로 열람 | 새 사진 알림 | 원본 화질 | 오픈소스·내 저장소 |
|---|---|---|---|---|
| **패밀리앨범** (국내 최다 사용) | ❌ 전원 앱 설치 필수 | ⭕ | ❌ 무료판은 압축 | ❌ |
| **Clann** (상용) | ⭕ | ⭕ | ⭕ | ❌ 남의 회사 서버 |
| **Immich** (오픈소스 1위) | ⭕ | ❌ 없음 | ⭕ | ⭕ |
| **photo_heaven** | ⭕ | ⭕ | ⭕ | ⭕ |

특히 **패밀리앨범은 브라우저로 링크만 눌러 보는 기능이 아예 없다.** 이게 이 프로젝트가 존재하는 첫 번째 이유다.

> **정직한 대안 검토**: `Immich`를 설치하면 위 요구사항의 70~80%가 코딩 없이 해결된다. 그럼에도 만드는 이유는 (1) Immich에 새 사진 알림이 없고, (2) 구글포토 대체용이라 조부모님께 보여드릴 화면이 아니며, (3) 설치·운영 난이도가 높기 때문이다. **만약 위 세 가지를 감수할 수 있다면 Immich를 쓰는 것이 합리적이며, 이 프로젝트는 불필요하다.**

## 2. 사용자

### 주요 사용자

**① 부모 (업로더) — 2명**
- **누구**: 곰곰님과 배우자
- **상황**: 아기 사진을 찍은 직후, 폰에서 바로
- **목표**: 한 번 올리면 양가 어른들께 전달되는 것. 카톡 두 번 안 보내는 것

**② 조부모·가족 (뷰어) — 10명 내외**
- **누구**: 양가 부모님 등 초대된 가족
- **상황**: 문자 알림을 받았을 때, 또는 손주 생각날 때 아무 때나
- **목표**: 어렵지 않게, 최신 사진을 한눈에 보는 것

> **규모 확정**: 불특정 다수가 가입하는 서비스가 **아니다.** 우리 가족(10명 내외)만 쓴다. 따라서 MAU 같은 지표, 회원가입 시스템, 결제, 고객지원은 전부 범위 밖이다.

### 향후 방향 — 오픈소스 공개

서비스로 키우지 않고 **코드를 공개**한다. 다른 부모들은 각자 자기 서버에 설치해서 쓴다.

이 결정이 만드는 것에 미치는 영향:
- 곰곰님이 남의 아기 사진을 보관하지 않는다 → **보안 책임·법적 책임·서버 비용이 붙지 않는다**
- 대신 **가족 정보(이름·전화번호·링크 주소·암호)가 코드에 단 한 글자도 박히면 안 된다**
- 대신 **남이 설치할 수 있는 설명서가 필요하다** (Phase 3)

### 사용자 시나리오

**부모**
1. 아기 사진을 찍는다
2. 폰 브라우저로 사이트를 열고 사진 여러 장을 한 번에 올린다
3. 원하면 "오늘 처음 뒤집었어요" 같은 한 줄을 붙인다
4. 끝. 양가에 각각 보낼 필요 없음

**조부모**
1. 문자로 "새 사진이 올라왔어요" 링크를 받는다 *(Phase 2)*
2. 링크를 누른다 → 브라우저가 열린다 (앱 설치 없음)
3. 처음 한 번만 네 자리 암호를 넣는다 (폰이 기억하므로 다음부터는 생략)
4. 최신 사진부터 큰 화면으로 본다

## 4. 사용자 흐름

### 부모 (올리기)
```
사이트 접속 → 관리자 암호 → 사진 선택(여러 장) → 업로드 → 한 줄 메모(선택) → 끝
```

### 조부모 (보기)
```
문자 링크 클릭 → 암호 4자리(처음 1회만) → 최신 사진 화면 → 사진 탭하면 크게
```

### 상세 흐름

1. **비밀 링크**: 주소는 추측 불가능한 무작위 문자열. 예: `photo-heaven.app/a/x7k2m9p4q1`
2. **암호 입력**: 네 자리. 맞으면 브라우저에 30일짜리 쿠키 저장 → 다음부터 안 물어봄
3. **사진 화면**: 최신순. 화면용 축소본을 먼저 보여줘서 빠르게 뜨고, 탭하면 원본
4. **업로드**: 부모만. 원본은 그대로 저장하고, 화면용 축소본을 따로 만들어 둠

## 5. 성공 기준

이 프로젝트가 "됐다"는 기준. **전부 실제로 해보고 확인한다.**

- [ ] 조부모님이 **곁에서 도와드리지 않아도** 링크 → 암호 → 사진 보기에 성공하신다
- [ ] 부모가 폰에서 사진 10장을 올리는 데 **30초 이내**
- [ ] 조부모님이 "다시 보내줘"라고 요청하는 횟수가 **0에 수렴**한다
- [ ] 구글에 아기 이름이나 링크를 검색해도 **아무것도 안 나온다**
- [ ] 실제 인터넷 주소로 접속된다 (내 컴퓨터에서만 되는 상태 ❌)
- [ ] 사진이 **원본 화질로** 보관된다 (패밀리앨범 무료판의 압축 문제를 반복하지 않는다)
- [ ] 코드 전체를 GitHub에 그대로 올려도 **가족 정보가 하나도 노출되지 않는다**

## 6. 안 만드는 것 (Out of Scope)

> AI에게 코드를 시킬 때 이 목록을 반드시 함께 보여주세요.

- **회원가입·로그인 시스템** — 이유: 가족 10명이 쓴다. 조부모님께 로그인을 시키는 순간 없애려던 그 불편이 돌아온다
- **얼굴 인식 자동 분류** — 이유: 서버 사양과 개발 기간이 크게 늘어난다. 사진 몇 천 장에 굳이 필요 없다
- **조부모 반응(하트·댓글)** — 이유: 곰곰님이 이번에 안 고르셨다. 데이터 구조에 자리만 남겨둔다
- **영상** — 이유: "되면 좋고" 수준. 사진의 수백 배 용량이고 변환 처리가 필요하다 → Phase 3
- **불특정 다수 가입, 결제, 고객지원** — 이유: 서비스가 아니라 오픈소스다
- **사진 편집·보정** — 이유: 폰 기본 앱이 이미 잘 한다
- **앨범 수동 정리(폴더·태그)** — 이유: 날짜순만으로 충분하다. 조부모님께는 오히려 복잡함
